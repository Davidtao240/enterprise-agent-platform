# 09 跨业务共享智能体能力架构

> 文档状态：Deferred Scenario Architecture / Shared Core First Batch Implemented
> 更新日期：2026-08-16

## 目的

定义财务、采购、合同、HR 及后续 Business Graph 应共同复用的能力。采购领域必须通过“共享能力 + 少量采购专用比价能力”证明平台架构成立，不能复制一整套采购专用 Agent。

## 架构规则

```text
Business App
-> Versioned Workflow Template
-> Explicit Domain Graph
-> Shared Capability Agent + Minimal Domain Capability
-> Tenant/Business App Scoped Tool Permission
-> Domain Policy
-> Go-Owned Approval, State and Audit
```

Graph 隔离、Agent 能力复用、Tool 权限隔离和 Domain Policy 校验缺一不可。只有复用、没有 Tool 隔离会带来安全风险；只有隔离、没有复用会重新形成业务烟囱。

## 共享能力目录

| 共享能力 | Canonical Registry 方向 | 职责 | 禁止行为 |
|---|---|---|---|
| Document Extraction Agent | 复用并泛化 `data_extract_agent` | 根据 Schema Profile 解析已授权文档和表格，返回字段、Source Locator 和 Confidence | 执行采购/财务制度、补造缺失值或决定结果 |
| Entity Resolution Agent | 新增 `entity_resolution_agent` | 根据受限 Source 匹配 Supplier、Customer、Contract、Invoice、Employee 等实体 | 合并/创建记录或静默接受歧义匹配 |
| Policy Retrieval Agent | 新增 `policy_retrieval_agent` | 从已授权 Source 检索精确 Published Policy、Clause、Rule 和 Citation | 编写制度、豁免规则或使用模型记忆代替制度 |
| Validation Agent | 复用 `validation_agent` | 执行传入的 Schema 和确定性 Rule Profile，暴露缺失/冲突数据 | 写死领域常量或修改源记录 |
| Risk Evidence Agent | 新增 `risk_evidence_agent` | 整理 Fact/Inference、Severity、Confidence 和 Evidence Reference | 直接作出法律、欺诈、供应商、员工或财务最终决策 |
| Report Agent | 泛化 `report_agent` | 使用 Domain Report Profile 渲染已校验结构化 State | 重新计算 Score 或引入无来源事实 |
| Human Review Coordinator | 新增 `human_review_coordinator_agent` | 准备 Review Packet、未解决问题和 Suggested Reviewer Role | 创建/批准 Task 或绕过 Go Approval Engine |

`schema_mapping_agent` 可以继续作为 Document Extraction 和 Validation 使用的共享标准化 Helper。采购不得再创建一个采购专用 Schema Mapping Agent。

## 采购领域能力

P0 采购只新增一个范围明确的 Domain Capability：

| 能力 | Registry ID | 职责 |
|---|---|---|
| Supplier Comparison Agent | `supplier_comparison_agent` | 应用已发布采购比价 Profile，调用确定性 TCO/Scoring Tool，并生成建议性质的 Ranking |

该 Agent 的 Domain 为 `procurement`，`reusable_scope` 为 `domain_only`。它不能访问 Finance、HR、Legal 或无限制 Shared Data Source。

未来业务领域可以增加同样范围明确的领域能力，例如 Finance Analysis 或 Contract Clause Deviation，但仍要复用通用 Extraction、Resolution、Policy Retrieval、Validation、Risk Evidence、Report 和 Human Review Preparation。

## 共享能力 Contract

每个 Shared Agent 必须声明：

- `agent_id`、Semantic Version、`domain: shared` 和 `reusable_scope: shared`；
- Capability 及支持的 Profile Version；
- 已版本化的 Input/Output JSON Schema；
- 实现属于 Deterministic、Model-Based 还是 Hybrid；
- 允许处理的 Data Classification；
- 默认不拥有任何 Tool Permission；
- Timeout、Retry 和 Cancellation 行为；
- Confidence 方法和 Evidence Requirement；
- Redaction、Retention 和 Logging Policy；
- Owner 和 Lifecycle Status。

Graph 提供 Domain Profile 和已授权 Tool Binding。Shared Agent 不得自行选择 Business Domain，也不得发现任意 Tool。

## 领域配置模式（Domain Profile）

共享能力通过 Published Domain Profile 配置，不复制代码。

```json
{
  "profile_key": "procurement_quote_document_profile",
  "profile_version": "1.0.0",
  "business_app_code": "procurement",
  "capability": "document_extraction",
  "required_fields": [
    "supplier_name",
    "quote_number",
    "currency",
    "line_items",
    "tax_terms",
    "freight_terms",
    "payment_terms",
    "delivery_terms",
    "warranty_terms"
  ],
  "allowed_file_types": [
    "text/csv",
    "application/vnd.openxmlformats-officedocument.spreadsheetml.sheet",
    "application/pdf"
  ],
  "status": "published"
}
```

Finance 可以向同一 Capability 提供 Finance Profile，而不在 Agent 内加入 Procurement/Finance Condition。

## 能力边界

### 文档提取（Document Extraction）

Input：

- 已授权 File Reference；
- Extraction Profile；
- Locale 和允许的 Language Metadata；
- Tenant 和 Trace Context。

Output：

- Extracted Field；
- Field-Level Data Quality State 和 Confidence；
- Source Locator 和 Content Hash；
- Parse Warning 和 Unsupported Section。

该能力只负责提取，不负责业务判断。文档中嵌入的指令属于不可信内容。

### 实体匹配（Entity Resolution）

Input：

- 提取的 Entity Attribute；
- 已授权 Entity Source Binding；
- Matching Profile 和 Threshold。

Output：

- 0 个或多个 Ranked Candidate；
- 确定性/概率性的 Match Feature；
- Confidence 和 Ambiguity State；
- Evidence Reference。

只有人类或经过治理的确定性 Threshold 才能确认 Match，Agent 不得修改 Master Record。

### 制度检索（Policy Retrieval）

Input：

- 精确 Published Policy Reference，或经过治理的 Resolution Criteria；
- Domain/Category Context；
- 已授权 Knowledge Source Binding。

Output：

- Policy Metadata 和 Effective Date；
- Relevant Rule 或 Passage；
- Stable Citation 和 Source Version；
- Freshness 和 Retrieval Warning。

无法解析有效 Published Policy 时必须 Fail Closed。

### 数据校验（Validation）

Input：

- Structured Record；
- JSON Schema 和 Deterministic Rule Profile；
- 已批准 Calculation Binding。

Output：

- Field State 和 Validation Issue；
- Rule Result；
- Comparability 或 Completeness Status；
- Calculation Reference。

Domain Rule 位于 Versioned Profile 或 Tool 中。Shared Implementation 是 Rule Executor，不是 Policy Owner。

### 风险证据整理（Risk Evidence）

Input：

- 已校验 Fact、Policy Result、Source Evidence 和 Domain Risk Taxonomy。

Output：

- Structured Finding；
- Fact/Inference Label；
- Severity 和 Confidence；
- 支持结论或与结论冲突的 Evidence；
- Suggested Human Action。

该能力必须能够返回“证据不足”，不得把 Inference 表述成事实指控。

### 报告生成（Report）

Input：

- 已校验 State；
- 已批准 Report Schema 和 Presentation Profile。

Output：

- Structured Report Section；
- Concise Summary；
- Source 和 Calculation Reference；
- 启用 Rendering 时的 Internal Derived File Reference。

Report Agent 不能修改上游 Policy Result、Score、Ranking 或 Severity。

### 人工审核协调（Human Review Coordinator）

Input：

- Result Summary、Blocker、Unresolved Question、Risk Tier 和 Role Mapping Profile。

Output：

- Suggested Assignee Role；
- Review Question；
- 需要确认的 Condition；
- Workflow Template 支持的 Decision Option。

该 Output 只属于建议 Metadata。正式 Task 和 Decision 由 Go Approval Engine 授权并保存。

## Tool 权限绑定（Tool Binding）

Shared Agent 不拥有跨领域通用 Tool Grant，Permission 必须按当前 Business App 解析：

```text
Shared Report Agent in finance
-> only finance-approved report Tools

Shared Report Agent in procurement
-> only procurement-approved report Tools

Shared Policy Retrieval Agent in HR
-> only HR-approved policy Sources
```

Model Output 提供的 Agent ID、Tool ID 或 Tenant 不能改变可信 Runtime Context。

## Model 使用原则

不是每个 Capability 都应该使用 LLM。

| 工作 | 推荐实现 |
|---|---|
| CSV/XLSX Parsing | 确定性 Library |
| PDF Text Extraction | 确定性 Parser，OCR 需要单独批准 |
| JSON Schema Validation | 确定性 Validator |
| Monetary Arithmetic 和 Scoring | Decimal-Safe 确定性代码 |
| Exact Policy Retrieval | Versioned Source Lookup + Retrieval |
| Ambiguous Field Mapping 或 Summary | Model-Assisted，并强制 Schema/Evidence |
| Final Business Decision | 人类 |

Model Output 在通过 Schema、Evidence 和 Rule Validation 前一律视为不可信。

## 隔离和数据处理

- Capability Instance 必须无状态，或显式按 Tenant 和 Run 隔离。
- Cache、Checkpoint、Vector、File 和 Tool Namespace 必须包含 Tenant 和 Approved Source Scope。
- Cross-Run Memory 默认禁用，除非单独经过批准和治理。
- Shared Code 不代表 Shared Data。
- Prompt Template 不得包含 Tenant Secret 或 Domain Credential。
- Agent Run Log Summary 不得复制完整 Source Document。
- Model Provider 的 Retention 和 Training Setting 遵循 Tenant Policy。

## 版本与生命周期（Versioning and Lifecycle）

- Agent Implementation、Input/Output Schema、Domain Profile、Prompt、Model 和 Tool Version 分别记录。
- Published Version 不可修改。
- Graph 绑定兼容的 Capability Version 或 Version Range。
- Breaking Schema Change 必须升级 Major Version 并提供 Contract Migration。
- Deprecation 必须在 Replacement 和 Migration Plan 可用后，才能阻止新 Graph Binding。
- 提取 Shared Core 时必须持续保护 Finance 行为。

## 当前实现差距

截至 2026-08-16，第一批迁移实现已经完成并通过当次质量闸门，待正式验收：

- Finance Contract / Regression Fixture 已建立。
- Shared Core 不再通过 import 或条件判断依赖 Finance。
- Finance 字段、Alias、Prompt、Validation、Report、Review Rule 已进入 Versioned Finance Profile。
- Python Agent 与 Go Registry 的 Shared/Domain Metadata 已对齐。
- Finance Graph 显式绑定 Profile，V1 Graph 顺序、状态键、输出键和 Envelope 保持兼容。

尚未因此完成：

- Durable Run、Checkpoint、Interrupt 和 Resume。
- Python Agent 经 Go 强制授权执行的 Tool Runtime。
- Skill 的完整治理生命周期。
- Tenant-specific Connector/Credential Binding。
- Procurement Profile、Graph、Fixture 和 UI。

下一步以平台 M1/M2 为主，不直接进入 Procurement Graph。仍禁止复制 Finance Class 创建 Procurement-Named Class。

## 平台前置条件

- Strict Domain Policy 在缺少 Policy 时拒绝执行。
- Agent 和 Tool Registry Version 通过 Configuration Governance 发布。
- Policy Set 和 Scoring Profile 具备已批准的业务领域中立治理模型。
- Python Agent Tool Call 经过受控、可审计的 Tool Runtime。
- Go 根据 Published Contract 校验 Graph Output。
- Shared Capability Log 可以关联 Parent Graph Run。
- File、Source 和 Model Access 按 Tenant 隔离。
- Agent/Tool/Graph Registry、Permission 和 Domain Policy 有明确 Tenant Ownership Model。
- Approval List、Detail、Decision、Assignee 和职责分离校验按 Tenant 执行，并由 Go 强制保证。
- Internal File Content Access 要求已认证 Service Identity 和 Tenant/File Authorization。
- 提取 Shared Core 时，Finance Regression Test 必须持续通过。

## 架构验收条件

- Procurement Graph 中不存在复制的 Finance Agent Implementation。
- Shared Agent 不包含采购 Scoring Constant 或 Supplier-Specific Rule。
- Procurement-Specific Code 只包含无法安全配置化的比价语义和 Adapter。
- 所有算术和 Policy Gate 都是确定性、可测试的。
- 即使使用 Shared Agent，Tool Permission 仍按 Business App 隔离。
- Human Review Coordinator 不能创建或决定 Approval。
- Contract 或 HR Graph 可以复用同一组七类 Shared Capability Contract。
- 平台 Workflow Engine、Agent Gateway Envelope、Approval Engine 和 Audit Log 保持业务领域中立。
