# 06 采购智能体输入输出契约

> 文档状态：Deferred Scenario Contract
> 说明：进入 Phase B 前必须与平台 V2 Run/Tool Contract 重新做跨栈兼容审查。

## 目的

定义 Go Agent Gateway 与 `procurement_quote_review_graph` 之间的版本化数据契约。本规范扩展 `docs/02_ARCHITECTURE/AGENT_IO_CONTRACT.md` 中的平台统一 Envelope，不替代平台规范。

## 数据契约规则（Contract Rules）

- Request 和 Response 使用 UTF-8 JSON。
- 平台 Envelope 保持业务领域中立。
- 采购数据只放在 `input` 和 `output.data` 下。
- 未知值使用 `null` 并附带 Data Quality State，不得省略或替换为 0。
- 重要事实和 Finding 必须包含 Evidence Reference。
- Output 只保存简洁的结构化理由，不保存隐藏 Chain of Thought。
- Go 后端必须在保存成功 Node Result 前校验 Response Schema。

## 请求校验（Request Validation）

以下 Envelope Field 为必填：

- `trace_id`；
- 值为 `procurement` 的 `business_app_code`；
- `workflow_template_key`；
- 值为已注册采购 Graph 的 `graph_key`；
- `workflow_instance_id`；
- `node_instance_id`；
- `input.contract_version`；
- `input.procurement_case`；
- `input.file_ids`；
- `input.configuration_refs`；
- `context.tenant_id` 和 `context.user_id`。

服务必须拒绝未知 `contract_version`，不得静默兼容语义不确定的新旧 Contract。

## 标准化报价结构（Normalized Quote）

`normalized_quotes` 中每个对象至少包含：

```json
{
  "quote_id": "quote_alpha",
  "supplier_ref": "supplier_alpha",
  "source_file_id": "file_quote_a",
  "quote_number": "A-2026-7788",
  "quote_date": "2026-07-12",
  "valid_until": "2026-08-12",
  "currency": "CNY",
  "line_items": [],
  "commercial_terms": {
    "tax_included": true,
    "freight_amount": 0,
    "payment_terms": "验收后 30 天付款",
    "delivery_date": "2026-08-03",
    "warranty_months": 36
  },
  "normalized_tco": {
    "amount": 590000,
```

```json
{
  "evidence_id": "ev_beta_payment_01",
  "source_type": "uploaded_file",
  "source_id": "file_quote_b",
  "locator": {
    "page": 2,
    "sheet": null,
    "cell_range": null,
    "json_path": null
  },
  "field": "commercial_terms.payment_terms",
  "excerpt": "预付 50%",
  "excerpt_hash": "sha256:example",
  "confidence": 0.99,

```

持久化的 `excerpt` 必须满足审核所需的最小范围，并根据 Tenant Policy 脱敏。`excerpt_hash` 针对 Canonical Source Segment 计算，但不能代替对授权 Source Evidence 的保留。

`score_status` 只能是 `scored` 或 `not_scored`。不可比较供应商的 `total_score` 和 `rank` 必须为 `null`。

## 业务成功与技术失败的区分

- `status: succeeded` 表示 Graph 执行完成，且 Output 通过 Schema 校验。
- `output.data.recommendation.status: insufficient_information` 是有效业务结果。
- `status: failed` 表示 Execution、Authorization、Configuration、Source Access 或 Contract Integrity 失败。
- `status: retrying` 和 `cancelled` 遵循平台 Contract。

## 错误结构（Error）

```json
{
  "run_id": "run_proc_002",
  "graph_key": "procurement_quote_review_graph",
  "status": "failed",
  "output": {},
  "usage": null,
  "error": {
    "code": "SCORING_PROFILE_INVALID",
    "message": "评分权重合计必须为 100。",
    "retryable": false,
    "stage": "validation",
    "details": {
      "scoring_profile": "procurement_general_goods_v1@1.0.0"
    }
  }
}
```

当前平台基础 Error Model 可能需要向后兼容地扩展 `retryable`、`stage` 和结构化 `details`。在扩展完成前，必须把这些值保存在 `output` 或 Agent Run Log 的 `error_json` 中，且不能破坏统一 Envelope。

## 错误码（Error Code）

| Code | 是否可重试 | 含义 |
|---|---|---|
| `PROCUREMENT_INPUT_INVALID` | 否 | 必需采购 Input 无效 |
| `FILE_ACCESS_DENIED` | 否 | File Tenant 或 Permission 校验失败 |
| `DOCUMENT_UNSUPPORTED` | 否 | P0 不支持该文件 |
| `DOCUMENT_EXTRACTION_FAILED` | 视原因而定 | Document Extraction 失败 |
| `ENTITY_SOURCE_UNAVAILABLE` | 是 | Supplier Source 暂时不可用 |
| `SUPPLIER_IDENTITY_AMBIGUOUS` | 不进行技术重试 | 需要人工确认 |
| `POLICY_NOT_PUBLISHED` | 否 | 没有可用 Published Policy |
| `POLICY_RETRIEVAL_FAILED` | 视原因而定 | 无法读取已批准 Source |
| `SCORING_PROFILE_INVALID` | 否 | Profile Schema 或 Weight 无效 |
| `FX_SOURCE_UNAVAILABLE` | 视原因而定 | 已批准 FX Data 不可用 |
| `TOOL_NOT_ALLOWED` | 否 | Agent/Tool/Business App Permission 被拒绝 |
| `DOMAIN_POLICY_VIOLATION` | 否 | Domain Boundary 校验失败 |
| `OUTPUT_SCHEMA_INVALID` | 默认不自动重试 | Graph 返回无效 Contract |
| `MODEL_TIMEOUT` | 是 | 已批准 Model 超时 |
| `GRAPH_EXECUTION_FAILED` | 视原因而定 | 未分类 Graph Failure |
| `CANCELLED` | 否 | 收到授权取消请求 |

## 数据最小化

- Agent Run Log 的 Input/Output Summary 不得复制完整报价文件。
- Secret、Access Token、银行账号、个人电话和无必要个人数据必须脱敏。
- Prompt 和 Model Log 遵循 Tenant Retention Policy。
- 禁止跨 Tenant 共享 Cache Key、Vector Namespace、File Reference 或 Model Context。
- 原始 Model Prompt 和 Response 不能作为权威业务记录。
- P0 Demo 的 Source/Derived File 默认保留 90 天，Archived Decision Package 和 Audit Log 默认保留 365 天。
- Raw Model Prompt/Response 默认不持久化；获批的调试记录最多保留 30 天。
- Supplier Bank Account 不属于允许的 Input/Output Schema。

## 版本管理（Versioning）

- `contract_version` 在 P0 批准后采用 Semantic Versioning。
- 增加可选字段可以升级 Minor Version。
- 删除、重命名或改变字段语义必须升级 Major Version。
- Workflow Template、Graph、Agent、Policy、Scoring 和 Tool Version 分别记录。
- Archived Run 必须能按原 Contract Version 读取。

## 数据契约测试（Contract Test）

必须提供以下 Fixture：

- 合法 Success Response；
- `insufficient_information` Success Response；
- Technical Failure Response；
- Unknown Field 和 Missing Required Field 拒绝；
- `null` 与 0 的差异处理；
- Evidence Reference 完整性；
- Scorecard 算术一致性；
- Tenant 和 File Ownership 拒绝；
- Go/Python 对扩展 Error 的向后兼容解析。
