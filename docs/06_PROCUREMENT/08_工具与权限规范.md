# 08 采购工具与权限规范

> 文档状态：Deferred Scenario Security Specification
> 更新日期：2026-08-16
> 本文必须通过平台 M2 Tool Execution Gateway 和 M3 Connector 强制执行；Registry/List 本身不构成授权边界。

## 目的

定义采购报价审查 P0 所需的最小 Tool Catalog、Permission、Risk Level 和 Execution Control。

Agent 注册不代表自动获得 Tool 权限。每次 Tool Call 都必须存在当前 Tenant 和 `procurement` Business App 下有效的 Agent-to-Tool Permission，并通过 Domain Policy 校验。

## P0 Tool 原则

1. Tool 是职责单一的受控操作，不是无限制 Database 或 Shell Access。
2. P0 Agent Tool 只允许 Read-Only 操作或纯确定性 Transformation。
3. 最终 Archive 是 Human Approval 后由 Go System Node 执行的动作，不是 Agent Tool。
4. P0 Permission 中不包含任何对外 Side Effect Tool。
5. Tool Input/Output 必须经过 Schema Validation 并可审计。
6. Tenant、User、Graph、Agent、Workflow、Node、Trace 和 Idempotency Context 必须完整传递。
7. Shared Agent 只能获得当前 Business App 已授权的 Tool。

## 建议 Tool 目录（Tool Catalog）

| Tool ID | Domain | Shared | Risk | Mode | 用途 |
|---|---|---:|---|---|---|
| `read_authorized_file` | shared | 是 | low | Read | 读取 Tenant 下属于当前 Workflow 的文件 |
| `parse_csv` | shared | 是 | low | Pure | 解析受支持 CSV |
| `parse_excel` | shared | 是 | low | Pure | 解析受支持 XLSX |
| `extract_pdf_text` | shared | 是 | low | Pure/Read | 提取文本型 PDF 内容和 Locator |
| `validate_structured_record` | shared | 是 | low | Pure | 执行指定 JSON Schema 或 Rule Profile |
| `resolve_entity_candidates` | shared | 是 | medium | Read | 查询限定 Entity Source 并返回候选 |
| `retrieve_published_policy` | shared | 是 | medium | Read | 检索精确 Published Policy Version |
| `build_evidence_reference` | shared | 是 | low | Pure | 标准化 Source Locator 并计算 Hash |
| `render_structured_report` | shared | 是 | medium | Pure/Write File | 把已校验 Report Data 渲染为内部文件 |
| `query_supplier_master` | procurement | 否 | medium | Read | 读取已批准 Supplier Identity 和 Status |
| `query_procurement_policy` | procurement | 否 | medium | Read | 未使用通用 Policy Retrieval 时读取采购规则 |
| `query_fx_snapshot` | procurement | 否 | medium | Read | 读取已批准的 Versioned FX Rate |
| `calculate_quote_tco` | procurement | 否 | medium | Pure | 计算标准化 TCO |
| `calculate_weighted_score` | procurement | 否 | medium | Pure | 应用已批准 Scoring Profile |
| `check_supplier_restrictions` | procurement | 否 | high | Read | 检查已批准 Restricted/Suspended Supplier Data |

`render_structured_report` 可以创建内部 Derived File，但不能 Publish、Send 或 Archive。相同 Content Hash 和 Workflow Node 的调用必须幂等。

## 明确禁止的 Tool

P0 Agent 不得注册或获得下列 Tool ID 或同等能力：

- `create_purchase_order`；
- `approve_purchase_order`；
- `send_rfq`；
- `send_supplier_email`；
- `negotiate_quote`；
- `create_supplier`；
- `update_supplier_bank_account`；
- `award_supplier`；
- `sign_contract`；
- `approve_invoice`；
- `initiate_payment`；
- 无限制 SQL、HTTP、Filesystem、Shell 或 Browser Execution。

Canonical Capability Name 和 Migration Alias 由 `09_跨业务共享智能体能力架构.md` 定义。

| Agent Capability | P0 允许的 Tool | Business App |
|---|---|---|
| Document Extraction | `read_authorized_file`、`parse_csv`、`parse_excel`、`extract_pdf_text`、`build_evidence_reference` | `procurement` |
| Entity Resolution | `resolve_entity_candidates`、`query_supplier_master`、`build_evidence_reference` | `procurement` |
| Policy Retrieval | `retrieve_published_policy`、`query_procurement_policy`、`build_evidence_reference` | `procurement` |
| Validation | `validate_structured_record`、`query_fx_snapshot`、`calculate_quote_tco` | `procurement` |
| Supplier Comparison | `calculate_quote_tco`、`calculate_weighted_score`、`query_fx_snapshot` | `procurement` |

| Human Review Coordinator | P0 不允许调用 Tool | `procurement` |

Human Review Coordinator 只返回建议 Metadata，不得把 Approval Engine API 当作 Tool 调用。

## Tool 请求上下文（Request Context）

每次 Tool Call 必须包含或继承：

```json
{
  "tool_id": "calculate_quote_tco",
  "agent_id": "supplier_comparison_agent",
  "business_app_code": "procurement",
  "tenant_id": "tenant_001",
  "user_id": "user_requester_001",
  "trace_id": "trace_proc_001",
  "workflow_instance_id": "wf_proc_001",
  "node_instance_id": "node_analyze_001",
  "run_id": "run_proc_001",
  "idempotency_key": "wf_proc_001:node_analyze_001:calculate_quote_tco:quote_alpha",
  "input": {}
}
```

Tool Runtime 必须从已认证的平台调用中得到可信 Context，不能信任只由 Model Output 提供的 Tenant、User、Agent 或 Business App ID。

## 权限校验顺序（Authorization）

Tool 执行前必须依次：

1. 认证调用方 Service Identity；
2. 校验 Tenant、Workflow、Node、Graph 和 Run 关联；
3. 校验 Active Agent Version 和 Domain；
4. 校验 Active Tool Version 和 Domain；
5. 校验 `procurement` 下有效的 Agent-to-Tool Permission；
6. 校验 Procurement Domain Policy 允许 Agent Domain 和 Tool Domain；
7. 校验 Tool Risk 和 Operation Mode；
8. 按需校验 User、File 和 Source Access；
9. 校验 Input Schema 和 Size Limit；
10. 执行 Timeout、Rate、Concurrency 和 Idempotency Control；
11. 记录 Start 和 Result Audit Metadata。

任何步骤失败都必须拒绝调用。Policy 或 Permission 缺失时绝不能默认允许。

## 风险等级处理（Risk）

| Risk | P0 行为 |
|---|---|
| Low | 完成标准 Authorization 后执行 |
| Medium | 完成标准 Authorization 和详细 Audit 后执行 |
| High Read | 只有显式授权才执行，结果必须进入 Human Review |
| High Write | P0 Agent 不可用 |

Tool Risk 由能力和数据敏感度共同决定，不能只根据是否写入数据判断。

## Input 和 Output 要求

- 每个 Tool 都有 Versioned JSON Input/Output Schema。
- Monetary Value 使用 Decimal-Safe 表示和显式 Currency。
- Date/Timestamp 使用 ISO 8601。
- Unknown Value 使用 `null` 和 Data Quality State。
- Read Tool 返回 Source Version、Effective Time 和 Freshness。
- Calculation Tool 返回 Formula Version、Input、Intermediate Component、Rounding 和 Result。
- Source Tool 只返回最少字段，不返回 Credential 和无必要个人数据。
- Tool Output 在通过 Schema 和 Tenant 校验前视为不可信。

## 幂等与副作用（Idempotency and Side Effect）

- 对固定 Source/Configuration Version，Pure Tool 和 Read Tool 必须可重复执行。
- Derived Report 使用 Content Hash 和 Workflow Node 生成 Idempotency Key。
- Retry 不得重复创建 Report File。
- P0 Tool 不得修改 Supplier、Procurement、Contract、Invoice 或 Payment System。
- Archive System Action 必须幂等，并且只在 Human Approval 后执行。

## 超时与失败处理（Timeout and Failure）

Tool 返回结构化 Error，包括 Code、Message、Retryability、Source 和经过安全过滤的 Detail。不能使用 Model Text 判断 Authorization Error 是否可以重试。

建议 Error Code：

- `TOOL_INPUT_INVALID`；
- `TOOL_NOT_FOUND`；
- `TOOL_NOT_ALLOWED`；
- `TOOL_DOMAIN_VIOLATION`；
- `TOOL_SOURCE_UNAVAILABLE`；
- `TOOL_SOURCE_STALE`；
- `TOOL_TIMEOUT`；
- `TOOL_OUTPUT_INVALID`；
- `TOOL_CANCELLED`。

## Audit 和数据保护

Tool Audit Record 必须包含：

- Identifier 和 Version，不记录原始 Credential；
- Actor/Service、Tenant、Business App、Agent、Graph、Workflow、Node、Run 和 Trace；
- Authorization Decision 和 Risk Level；
- Input/Output Hash 或 Redacted Summary；
- Source Version 和 Freshness；
- Start、Finish、Duration、Status 和 Error Code；
- Idempotency Result。

Tool Log 不得记录完整报价、银行账号、Token、Connection String 或无限制 Supplier Record。

## 当前平台前置差距

采购实现前，必须确认 Python Agent 的 Tool Call 会经过 Go 中强制执行的 Tool Execution Path。Registry 只提供列表，不构成 Authorization Boundary。如果当前尚无受控 Runtime，必须先把它实现为业务领域中立的平台能力，再连接采购 Data Source 或 High-Risk Tool。

生产环境必须启用 Strict Domain Policy。缺少 Procurement Policy 或 Agent-to-Tool Permission 时必须拒绝执行。

当前 Registry 和 Agent-to-Tool Permission Schema 按 Business App 隔离，但没有 Tenant Ownership。采购上线前必须增加 Tenant Ownership，或正式定义“不可变全局配置 + Tenant-Specific Binding”的等价模型。任何 Tenant 都不能意外继承其他 Tenant 的 Data Source Credential 或 Tool Grant。

在实现 Tool Runtime 前，先完成 M1 Durable Run，使 ToolCall 能稳定关联 Run、Step、Checkpoint、Attempt 和恢复语义。后续 External Data Source 通过 Connector Binding 接入，Credential 只保存引用；高风险动作审批绑定不可变 Payload，并在执行后 Verify。

Agent 处理文件时使用的内部 File Content Path 必须要求已认证 Service Identity，并校验 File 与 Tenant/Workflow 的关联。仅持有 Storage Key 不能视为获得权限。

## Tool 数据契约测试

- 允许 Procurement 中已授权 Shared Agent 调用 Shared Tool；
- 缺少 Procurement Permission Record 时拒绝同一 Tool；
- Procurement Graph 调用 Finance-Only Tool 时拒绝；
- Finance Graph 调用 Procurement Tool 时拒绝；
- Tenant/File 不匹配时拒绝；
- Model 试图替换 Identity 或 Tool ID 时拒绝；
- 校验 Calculation Reproducibility 和 Decimal Handling；
- 校验 Stale Policy、Supplier 和 FX Source；
- 校验 Timeout、Cancellation、Retry 和 Idempotency；
- 确认没有注册或授权任何禁止的 Write Tool。
