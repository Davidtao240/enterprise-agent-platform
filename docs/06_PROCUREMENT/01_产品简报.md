## 产品定位

采购报价审查 Agent 将采购需求、供应商报价、供应商主数据和采购制度，转换成一份可追溯证据的供应商比价审查材料，交由人类审核人决策。

它是决策辅助 Workflow，不是自主采购员。系统可以标准化事实、执行已批准规则、计算确定性分数、识别风险并提出后续建议，但不得决定中标供应商、创建采购订单、联系供应商、修改供应商主数据或批准付款。

## 要解决的问题

采购审核人员经常需要重复处理以下工作，同时又必须对最终结果负责：

- 从格式不一致的报价文件中提取数据；
- 对齐单位、币种、税费、运费、交付条件和付款条件；
- 检查报价数量和必需材料是否满足制度要求；
- 比较 Total Cost of Ownership（TCO），而不是只比较单价；
- 识别制度例外、供应商风险和信息缺口；
- 生成每个结论都能回溯到原始证据的审查材料。

纯人工审核速度慢、标准不一致；完全自动选定供应商又不可接受，因为商业背景、利益冲突、谈判策略和决策责任仍属于人类。

## 目标用户

| 用户 | 核心诉求 |
|---|---|
| 采购申请人 | 提交完整且可比较的采购案例 |
| 采购分析人员 | 减少提取、标准化和比价工作 |
| 采购审核人 | 审查证据、例外、分数和建议 |
| 财务或预算负责人 | 确认预算和重大商务例外 |
| 合规或审计人员 | 追踪制度版本、证据、操作和决策 |
| 平台管理员 | 管理配置、权限、Tool 和模型使用 |

## P0 核心任务

当申请人提交一份采购需求和三份供应商报价时，平台应生成标准化、制度校验、评分和证据关联后的比价审查材料，帮助授权审核人作出并解释最终决策。系统可以接收两份报价用于例外分析，但不得在缺少已批准例外时给出供应商推荐。

P0 标准案例必须提供三份可比较报价。报价数量不足时必须存在已批准的制度例外；没有 `approved_exception_ref` 时返回 `insufficient_information`，不得静默地把案例当作合规。

P0 首个受控品类为 `IT.HARDWARE.LAPTOP`。支持 CSV、XLSX 和文本型 PDF，不包含 OCR、手写件和低质量扫描件。

## P0 用户流程

1. 申请人创建 `procurement_quote_review` Workflow。
2. 申请人填写采购需求并上传报价及支撑文件。
3. 共享能力完成文档提取、实体匹配、制度检索、数据校验、风险证据整理和报告生成。
4. 采购领域比价能力根据已批准的评分方案计算 TCO 和分数。
5. Graph 返回包含证据引用、置信度和未解决问题的结构化审查材料。
6. Go Workflow Engine 创建人工审核任务。
7. 授权审核人填写意见并批准或驳回。
8. Go 后端归档已批准结果，并记录完整 Audit Log。

## P0 范围

### 包含内容

- CSV、XLSX 和文本型 PDF 报价文件；
- 采购需求和报价完整性检查；
- 供应商实体候选匹配；
- 单位、数量、币种、税费、运费和付款条件标准化；
- 使用已批准公式进行 TCO 比较；
- 确定性制度校验和加权评分；
- 关联原始证据的风险发现；
- 明确标记为“决策辅助”的推荐结果；
- 归档前强制执行一次人工审核；
- 可追踪的 Workflow、Agent Run、Approval 和 Audit 记录；
- Tenant 和 Business Domain 隔离；
- 明确处理缺失、冲突和低置信度数据。

### 不包含内容

- 自动决定供应商中标或淘汰；
- 自动创建采购订单；
- 自动发送 RFQ 或联系供应商；
- 自动议价；
- 供应商准入或主数据变更；
- 发票批准或付款；
- 使用无授权外部数据源进行制裁名单筛查；
- P0 阶段处理手写或低质量扫描件；
- 多轮竞价或拍卖流程；
- 对合同效力给出法律结论；
- 使用 Tenant 文档训练模型。

## 产品原则

1. **先证据，后解释。** 每个重要事实、例外和建议必须关联来源或确定性计算。
2. **先规则，后模型判断。** 必填字段、算术、制度阈值和评分公式必须由确定性逻辑处理。
3. **人类拥有决策权。** 最终供应商决策属于授权人员，并由 Approval Engine 记录。
4. **Fail Closed。** 制度缺失、配置无效、实体无法确认或商务条件不可比较时，不得输出无条件推荐。
5. **禁止静默补值。** 未知值保持未知，除非已批准规则明确提供默认值。
6. **平台保持领域中立。** 采购通过 Business App、Workflow Template、Graph、Agent/Tool Registry 和 Domain Policy 接入。
7. **优先复用共享能力。** 不在采购领域重复实现提取、校验、检索、证据、报告和人工审核协调能力。

## 人类与 Agent 能力边界

Agent 系统可以：

- 提取并标准化提交的信息；
- 给出供应商实体匹配候选及置信度；
- 检索已发布的制度版本；
- 执行确定性校验和评分；
- 识别并解释制度例外；
- 按已批准评分方案对可比较报价排序；
- 生成推荐草案和人工审查材料。

只有授权人员可以：

- 确认存在歧义的供应商匹配；
- 豁免强制采购规则；
- 判断报价是否在商业上真正可比较；
- 决定供应商中标或淘汰；
- 批准预算或利益冲突例外；
- 授权对外沟通、采购订单、合同或付款。

P0 使用受控基准数据集进行验收。

| 指标 | 目标 |
|---|---|
| 支持模板的必填字段提取准确率 | 不低于 95% |
| 算术和确定性评分准确率 | 与基准计算 100% 一致 |
| 重大风险发现的证据覆盖率 | 100% |
| 无来源支撑的事实陈述 | 0 |
| Agent 自主完成最终供应商决策 | 0 |
| 人工审核覆盖率 | 100% |
| Workflow、Agent Run、Approval、Audit 的 Trace 覆盖率 | 100% |
| 跨 Tenant 或跨 Domain 数据泄露 | 0 |
| 基准 Demo 完成时间 | 不含人工阅读时间，10 分钟以内 |

准确率目标只适用于受控 P0 数据集，不代表对任意文档都能达到同等效果。

## P0 数据治理基线

- Demo 只使用虚构数据，不连接真实 Supplier、Employee、Bank 或 Contract 数据。
- 采购需求、报价和 Derived Report 按“企业内部机密”处理。
- P0 默认保留期：Source File 和 Derived File 90 天，Archived Decision Package 和 Audit Log 365 天。
- Raw Model Prompt/Response 默认不持久化；调试环境确需保存时最多保留 30 天，并执行 Redaction。
- Supplier Master 和 Restricted Supplier Snapshot 在 Workflow 启动时必须不超过 24 小时；FX Snapshot 必须记录 Effective Date 和 Version。
- Supplier Entity Match 的 High Confidence Threshold 为 `0.90`；低于该阈值必须人工确认。
- P0 不处理 Supplier Bank Account，不允许该字段进入 Prompt、Agent Output Summary 或 Audit Detail。
- Production Retention 和 Data Source Binding 必须由 Tenant-Specific Published Policy 覆盖默认值。
