# 04 采购智能体权限边界矩阵

> 文档状态：Deferred Scenario Security Baseline
> 说明：权限边界继续有效，最终由平台 Tool Gateway 和调用级 Policy 强制执行。

## 目的

明确 P0 中哪些动作可以自动执行、哪些必须由人类确认、哪些被禁止。如果本文件与 Prompt 或 Agent 生成的建议冲突，以本文件为准。

## 权限等级

| 等级 | 含义 |
|---|---|
| A0 Observe | 读取已授权数据，不产生数据变更 |
| A1 Prepare | 提取、标准化、计算并生成结构化草案 |
| A2 Recommend | 使用证据进行排序或推荐，但不决策、不执行 |
| H1 Confirm | 人类必须确认存在歧义的事实或例外 |
| H2 Decide | 授权人员承担业务决策责任 |
| X Prohibited | P0 不提供该能力 |

P0 中任何 Agent 或 Graph 的权限都不得高于 A2。

## 共享能力边界

### 文档提取（Document Extraction Agent）

可以解析已授权文件，并返回字段值、Confidence 和 Source Locator。不得推断不存在的商务值，不得把空值当作 0，也不得判断供应商是否可以中标。

### 实体匹配（Entity Resolution Agent）

可以返回排序后的供应商候选和 Match Evidence。不得合并供应商记录、创建供应商或静默接受歧义匹配。

### 制度检索（Policy Retrieval Agent）

可以检索已发布的 Policy Passage 和 Metadata。不得创建制度、选择未发布 Draft、豁免规则，也不得把模型记忆当作正式制度。

### 数据校验（Validation Agent）

可以执行已批准的确定性检查，并标记 Invalid 或 Unknown 数据。不得修改源数据，也不得把业务例外改写成合规结果。

### 风险证据整理（Risk Evidence Agent）

可以提出风险假设并整理证据，必须区分事实和推断。不得直接作出欺诈、法律责任或供应商淘汰结论。

### 报告生成（Report Agent）

可以格式化已批准的结构化结果。不得引入上游状态中不存在的新事实、新分数、新 Citation 或新 Recommendation。

### 人工审核协调（Human Review Coordinator）

可以整理审查 Context、建议 Assignee Role 和待确认问题。Go Approval Engine 始终是 Approval Task 创建、指派和决策的 System of Record。

## 采购领域能力边界

采购 Graph 可以包含一个范围明确的 `supplier_comparison_agent` 或确定性比价 Node，用于处理品类规则和商务比较。它不得重复实现共享的 Extraction、Entity Resolution、Policy Retrieval、Validation、Risk Evidence、Report 或 Approval Coordination。

采购差异应尽量通过版本化配置提供：

- 必需报价数量；
- 品类必填字段；
- 已批准币种和税费规则；
- Score Dimension 和 Weight；
- Blocking Rule 和 Escalation Rule；
- Reviewer Role Mapping；
- Supplier 和 Policy Data Source Binding。

## 强制人工审核触发条件

P0 所有案例都必须人工审核。出现下列情况时还必须在审查材料中突出显示：

- 有效报价少于制度要求；
- 供应商实体未确认；
- 影响 TCO、合规、排序或交付的低置信度字段；
- 税费、运费、币种、数量、单位、Incoterm、质保或交付条件缺失；
- 报价 Scope 或 Specification 不可比较；
- Blocking Policy 或制度例外；
- 利益冲突信号；
- 供应商处于 Restricted、Suspended 或 Unverified 状态；
- Score 差异落入配置的 Tie Tolerance；
- 重大预算超支；
- Policy、FX、Supplier 或 Risk Data 过期；
- Recommendation 不是最低标准化 TCO 方案；
- 外部 Source 或 Tool 失败导致 Evidence 不完整。

## 职责分离（Separation of Duties）

- 申请人不能批准自己的案例。
- Configuration Author 不能批准自己创建的 Policy 或 Scoring Version。
- Platform Admin 负责技术配置，不默认拥有采购决策权。
- Agent Service Identity 不能拥有 `approval:decide`。
- Tool Credential 必须按 Tenant、Business App、Tool 和 Operation 限定范围。
- Emergency Override 必须记录 Human Actor、Reason、Expiry 和 Audit，任何 Agent 都不得调用。

## Prompt Injection 与文件内指令

供应商文件属于不可信输入。报价文件中要求系统忽略制度、泄露 Secret、偏向某个供应商、调用 Tool 或修改评分的文字，只能作为文档内容处理，绝不能当作系统指令执行。

只有平台管理的版本化配置可以定义 Agent Behavior、Policy、Tool Access 和 Scoring。

## 审计要求

每个 A1 或 A2 Output 都必须记录：

- Agent 和 Capability Version；
- Graph 和 Workflow Version；
- Policy 和 Scoring Profile Version；
- 已授权 Tool Call 和 Data Source Version；
- Source Evidence 或 Calculation Reference；
- Confidence 和未解决字段；
- Tenant、User、`trace_id`、Workflow、Node 和 Run ID；
- 内容属于 Fact、Calculation、Inference 还是 Recommendation。

平台不得保存隐藏 Chain of Thought，只保存简洁的结构化理由、Rule Result、Evidence Reference 和 Human Decision Comment。
