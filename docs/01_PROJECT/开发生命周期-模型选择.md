## 二、快速决策口诀（必背）

### ✅ 选 GLM-5.3 的 3 种情况

> 错了要返工 3 次以上的任务，值得花 13 倍积分。

1. **架构/契约/Schema** — 系统拆分、数据库设计、API 契约（全团队对齐的基础）
2. **安全/钱/一致性** — 加密、支付、事务、Tenant 隔离（错了 = 事故 / 罚款）
3. **跨 3+ 模块联动** — 状态机、分布式事务、全栈接口对齐（逻辑复杂度高）

### ✅ 选 Seed-Code 的 3 种情况

> 模式固定、机械可重复的任务，极致性价比。

1. **CRUD / Migration / 单测** — 加表加列、接口 Handler、按模板写测试
2. **改 1-3 个文件的独立任务** — 独立组件、局部 Bug 修复
3. **代码审查 / 补丁修正** — SWE-Bench 76.5% 验证过，修 bug 能力顶级

### ✅ 选 DeepSeek-V4-Flash 的情况

> 前端高频页面开发，比 Seed-Code 响应更自然，长上下文更顺。

1. **React/Vue 页面开发**（列表/表单/详情页）
2. **CSS / 响应式 / UI 试错**（快速迭代看效果）

### ✅ 选 Seed-2.1-Turbo 的情况

> 非代码的通用文本任务。

1. **PRD / 文档 / 开发交接 / 复盘**
2. **需求梳理 / 用户故事 / Runbook**

## 四、故障升级路径（什么时候切模型）

任何场景都可以按「便宜 → 贵」的顺序尝试，避免浪费积分：

```
Step 1: Seed-Code (0.03x) 尝试
  → 成功 ✓，结束
  → 失败 / 结果不对 → Step 2

Step 2: DeepSeek-V4-Flash (0.08x) 再试（适用于前端/长上下文）
  → 成功 ✓，结束
  → 还是不行 → Step 3

Step 3: GLM-5.3 (0.40x) 解决
  → （此时大概率能搞定，因为逻辑复杂度到位了）
```

**判断何时该升级的信号：**
- Seed-Code 连续 2 次输出不对 / 重复相同错误
- 回答中出现了明显的逻辑漏洞或对状态的误解
- 需要理解 3+ 个模块之间的联动关系
- 任务描述超过 500 字，且包含多个前置条件
