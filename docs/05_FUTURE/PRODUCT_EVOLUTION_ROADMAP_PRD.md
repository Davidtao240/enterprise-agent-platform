# 产品演进路线 PRD：企业级 AI 智能体操作系统

> 版本：v1.0 · 状态：评审中 · 作者：产品组
> 文档定位：面向"业务智能体工作平台"向"企业 AIOS"演进的分期路线，包含里程碑、范围、验收标准与前端优先级路线图（R0~R8）。

---

## 1. 背景与问题定义

### 1.1 现状（2026-08）
平台已完成：RBAC 权限、Workflow Core（模板/实例/节点/状态机/Asynq）、Agent Registry & Gateway（含 Domain Policy）、Python Agent Service（6 个财务智能体 + LangGraph + RAG）、前端工作台（登录/财务中心/工作流详情/审批/审计）、审计可观测、Docker 部署。

### 1.2 已识别的核心差距（四账号实测 + 竞品对标）
1. **业务未真闭环**：知识库 embedding 为 mock、检索无法溯源；财务"上传→分析→出报告→审批→归档"链路松。
2. **智能体执行黑盒**：只给最终结果，无过程/工具调用/待办可视化，用户无法干预。
3. **多角色体验差**：权限不足时静默跳转、缺空态引导、仪表盘割裂且有样例数据掩盖故障。
4. **缺企业化要素**：无 AI 用量/额度/计费可视、无审批待办聚合、无 Build（低代码造智能体）能力。

### 1.3 竞品锚点
| 锚点 | 厂商 | 可借鉴 |
|---|---|---|
| TraeWork | 字节 | 三模式(Work/Code/Design)、工具面板(Todos/上下文/产物)、所见即所得迭代 |
| WorkBuddy | 腾讯 | 多 Agent 并行、团队管理、AI 额度/IP 白名单/工具权限、管理后台管人/AI/资产 |
| 金蝶灵基 | 金蝶 | 企业 AI 操作系统、Chat/Work/Build、Harness 五子系统、动作审批、Work↔Build 闭环 |
| 用友本体智能体/BIP6 | 用友 | 本体(Ontology)驱动、YonClaw 超级智能体、Harness 六层、三重验证+回滚 |

## 2. 产品愿景

> **让 AI 真正进入企业核心业务闭环 —— 构建企业级"AI 智能体操作系统（企业 AIOS）"：能创建、能编排、能执行、能治理、能进化。**

四层螺旋架构：
- **底座层 · Harness 确定性工程**：指令/验证/范围/状态/生命周期 → 把现有 approval/audit/policy/run-log 工程化为平台内核。
- **语义层 · 业务本体（Ontology）**：把 `contextbuilder` 升级为业务本体引擎，让模型"懂财务口径"。
- **执行层 · 智能体编排**：从单图运行走向多智能体协同 + 长程执行 + 断点续跑 + 产物回写。
- **体验层 · AI 原生工作台**：过程可见、可干预、可验收、可复用。

## 3. 演进里程碑（M1~M6）

> 命名沿用 `agentic/` 分支习惯（领域/里程碑）。每个里程碑含：目标、范围（含/不含）、交付物、验收标准（Gate）。

### M1 · AI 执行透明化（体验层打底）
- 目标：结束"黑盒执行"，让用户看到智能体在干什么、可干预。
- 范围：
  - R1 智能体执行过程可视化面板（Todos / 工具调用卡片 / 上下文引用 / 产物预览）。
  - SSE 流式事件模型升级（`run.started/step.updated/tool.called/artifact.ready`）。
  - 运行时支持"暂停 / 重试 / 中断 / 断点续跑"。
- 验收 Gate：
  - 财务报告流程全程，每一步工具调用事件实时上屏且可展开查看入参/出参。
  - 单次运行可从中途中断并续跑，状态与 `agent_run_logs` 完全一致。
  - 前端单元测试 ≥ 50%（工具面板组件）。
- 不含：RAG 实体化、审批中心。

### M2 · RAG 可信化 + 引用溯源
- 目标：修复"能用但不能用"，让财务知识可信。
- 范围：
  - 后端 embedding 换成真实向量（接入 Qwen/DeepSeek embedding 或本地模型），移除 mock。
  - 检索可视化：来源文档 + 相似度进度条 + 命中片段高亮。
  - 回答引用注脚（可点击定位到原文 chunk）。
  - 文档解析（PDF/Word/Excel）与断句入 chunk。
- 验收 Gate：
  - 上传真实财务制度文档，问"报销上限"能返回带来源引用的准确答案。
  - 检索结果全部有真实来源与相似度分数，无随机值。
- 不含：多集合跨库检索。

### M3 · 业务闭环：审批中心 + 全平台待办聚合
- 目标：打通"出结果 → 审批 → 归档"的企业闭环。
- 范围：
  - 全局"待办"入口聚合所有业务审批。
  - 审批页：AI 预审结论摘要 + 证据（凭证/单据）+ 一键通过/驳回/转人工。
  - 高危动作人工确认（承接现有 Approval Engine 的 Domain Policy）。
  - 财务中心端到端 Demo 完善（上传→分析→出报告→审批→归档）。
- 验收 Gate：
  - 用户在所有业务页均可看到统一待办并完成审批，操作全链路审计。
  - 高危动作无人工确认前不可执行，留痕完整。
- 不含：Build 低代码。

### M4 · 对话即工作台（体验层升级）
- 目标：从"纯聊天"到"任务工作台"。
- 范围：
  - 技能(Skill)选择、附件上传、知识库引用、多轮上下文压缩。
  - 产物预览 "选中元素 → 评论到对话 → AI 直接改"（对标 TraeWork）。
  - 上下文引用面板展示被引用的规则/文档。
- 验收 Gate：
  - 一次对话内可交叉引用知识库和上传附件完成报告并直接编辑产物。
- 含：R2。

### M5 · 组织级 AI 治理工作台
- 目标：面向 Admin/Manager 的企业化可运营。
- 范围：
  - R6：成员 AI 用量/额度、工具调用权限矩阵、IP 白名单、审计时间轴、危险操作拦截记录。
  - Dashboard 与 ManagerDashboard 合并去重，移除样例数据掩盖。
  - RBAC 权限矩阵前端可视。
- 验收 Gate：
  - Admin 可在单一视图查看成员用量、额度、审计，并可调整工具权限。
- 含：R6、R7。

### M6 · Build：低代码智能体工作台（护城河）
- 目标：让平台"长出新的业务智能体"，彻底贯彻"不加业务 if/else"。
- 范围：
  - 可视化工作流编排（触发→校验→工具→审批→回写）。
  - Skill 封装向导（把流程/规则沉淀为复用技能）并发布市场。
  - Agent 市场（安装/评分/版本）。
  - 业务本体(Ontology)编辑器（语义建模，承接 R5 升级）。
- 验收 Gate：
  - 非研发用户可在无代码情况下搭建一个新业务智能体并跑通全流程。
- 含：R5。

## 5. 风险与依赖

- **风险**：R1 依赖 SSE 事件模型升级（ADR-007 扩展）；R2/R4 依赖真实 embedding。
- **依赖顺序**：M1(R1) → M2(R4) → M3(R3) → M4(R2) → M5(R6/R7) → M6(R5)。
- **性能**：R1 需控制事件推送频率（节流失真），避免大并发抖动（此前已出现过 429/SSE 中断教训）。
- **数据**：R4 需在 `.env` 配置真实 embedding 模型与密钥，禁止 mock 兜底。
